# Database Design — FinVigil Central

FinVigil Central uses PostgreSQL 16+ as the relational persistence store. The database schema links Customer profiles, Credit Underwriting decisions, Financial Transactions, AML Anomaly Alerts, and Audit Logs.

---

## 1. Entity-Relationship Model Overview

```
customers (1)
  ├── (0..N) credit_applications (1) ── (1) credit_decisions
  ├── (0..N) transactions (1) ──────── (0..1) aml_alerts
  └── (0..N) aml_alerts
```

---

## 2. Table Specifications

### 2.1 `customers`
Stores user/customer credentials and profile information.
* `id` (BIGSERIAL PRIMARY KEY)
* `customer_uuid` (VARCHAR(64) UNIQUE NOT NULL) — Public unique identifier for the customer
* `name` (VARCHAR(255) NOT NULL)
* `email` (VARCHAR(255) UNIQUE NOT NULL)
* `phone` (VARCHAR(32) NOT NULL)
* `password_hash` (VARCHAR(255) NOT NULL) — BCrypt hashed password
* `status` (VARCHAR(32) DEFAULT 'ACTIVE' NOT NULL)
* `created_at` (TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP NOT NULL)
* `updated_at` (TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP NOT NULL)

### 2.2 `credit_applications`
Records credit evaluation requests.
* `id` (BIGSERIAL PRIMARY KEY)
* `application_uuid` (VARCHAR(64) UNIQUE NOT NULL)
* `customer_id` (BIGINT NOT NULL REFERENCES customers(id) ON DELETE CASCADE)
* `income` (NUMERIC(15, 2) NOT NULL)
* `employment_years` (INT NOT NULL)
* `loan_amount` (NUMERIC(15, 2) NOT NULL)
* `existing_loans` (INT NOT NULL)
* `credit_score` (INT NOT NULL)
* `debt_to_income_ratio` (NUMERIC(5, 4) NOT NULL)
* `application_status` (VARCHAR(32) DEFAULT 'PENDING' NOT NULL) — `PENDING`, `APPROVED`, `REJECTED`, `REVIEW`
* `created_at` (TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP NOT NULL)

### 2.3 `credit_decisions`
Stores ML underwriting results generated by the XGBoost risk model.
* `id` (BIGSERIAL PRIMARY KEY)
* `decision_uuid` (VARCHAR(64) UNIQUE NOT NULL)
* `application_id` (BIGINT NOT NULL REFERENCES credit_applications(id) ON DELETE CASCADE)
* `risk_score` (NUMERIC(5, 4) NOT NULL) — 0.00 to 1.00
* `risk_level` (VARCHAR(32) NOT NULL) — `LOW`, `MEDIUM`, `HIGH`
* `decision` (VARCHAR(32) NOT NULL) — `APPROVE`, `REVIEW`, `REJECT`
* `model_version` (VARCHAR(64) NOT NULL)
* `created_at` (TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP NOT NULL)

### 2.4 `transactions`
Live transaction stream records.
* `id` (BIGSERIAL PRIMARY KEY)
* `transaction_uuid` (VARCHAR(64) UNIQUE NOT NULL)
* `customer_id` (BIGINT NOT NULL REFERENCES customers(id) ON DELETE CASCADE)
* `amount` (NUMERIC(15, 2) NOT NULL)
* `transaction_type` (VARCHAR(32) NOT NULL) — `TRANSFER`, `PURCHASE`, `WITHDRAWAL`, `DEPOSIT`
* `merchant` (VARCHAR(255) NOT NULL)
* `transaction_timestamp` (TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP NOT NULL)
* `currency` (VARCHAR(8) DEFAULT 'INR' NOT NULL)
* `status` (VARCHAR(32) DEFAULT 'COMPLETED' NOT NULL)
* `created_at` (TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP NOT NULL)

### 2.5 `aml_alerts`
Suspicious transaction alerts generated by velocity rules and Isolation Forest model.
* `id` (BIGSERIAL PRIMARY KEY)
* `alert_uuid` (VARCHAR(64) UNIQUE NOT NULL)
* `customer_id` (BIGINT NOT NULL REFERENCES customers(id) ON DELETE CASCADE)
* `transaction_id` (BIGINT REFERENCES transactions(id) ON DELETE SET NULL)
* `anomaly_score` (NUMERIC(5, 4) NOT NULL) — Isolation Forest score
* `risk_level` (VARCHAR(32) NOT NULL) — `LOW`, `MEDIUM`, `HIGH`
* `rule_score` (NUMERIC(5, 4) NOT NULL) — Rule engine score
* `final_risk_score` (NUMERIC(5, 4) NOT NULL) — Weighted blend
* `reason` (TEXT NOT NULL) — Human-readable rationale
* `status` (VARCHAR(32) DEFAULT 'OPEN' NOT NULL) — `OPEN`, `UNDER_REVIEW`, `RESOLVED`, `FALSE_POSITIVE`
* `created_at` (TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP NOT NULL)

### 2.6 `audit_logs`
Immutable compliance and security audit trail.
* `id` (BIGSERIAL PRIMARY KEY)
* `event_type` (VARCHAR(64) NOT NULL)
* `entity_type` (VARCHAR(64) NOT NULL)
* `entity_id` (VARCHAR(128) NOT NULL)
* `action` (VARCHAR(255) NOT NULL)
* `timestamp` (TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP NOT NULL)

---

## 3. Database Indexes
* `idx_customers_uuid` on `customers(customer_uuid)`
* `idx_customers_email` on `customers(email)`
* `idx_credit_apps_uuid` on `credit_applications(application_uuid)`
* `idx_credit_apps_customer` on `credit_applications(customer_id)`
* `idx_credit_decisions_uuid` on `credit_decisions(decision_uuid)`
* `idx_transactions_uuid` on `transactions(transaction_uuid)`
* `idx_transactions_customer` on `transactions(customer_id)`
* `idx_transactions_timestamp` on `transactions(transaction_timestamp)`
* `idx_aml_alerts_uuid` on `aml_alerts(alert_uuid)`
* `idx_aml_alerts_customer` on `aml_alerts(customer_id)`
* `idx_aml_alerts_status` on `aml_alerts(status)`
* `idx_audit_logs_timestamp` on `audit_logs(timestamp)`
